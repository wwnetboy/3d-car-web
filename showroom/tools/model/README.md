### 坐标与取景

世界坐标以 +Y 向上，+X 指向车头。原件包围盒从 (−2.682, 0.004, −1.327) 延伸至 (2.762, 1.191, 1.327)。前后轮心约为 (1.64, 0.40, ±1.01) 和 (−1.37, 0.44, ±1.05)。头灯靠近 (2.38, 0.48, ±0.86)，尾灯环位于负 X 端。低机位可直接观察前灯下的分流槽以及前轮后方的侧向开口。

原件有 22 个节点、18 个按材质拆分的网格、11 种材质、1 张 1024 × 1024 轮胎法线贴图、0 段动画。车漆为 `accent`，风挡与透明轮罩共用 `glass`，前灯竖向灯片使用 `emit`，横向灯片使用 `blac`，尾灯环使用 `material`。座舱包含 `interior_accent`、`metal`、`chrome` 等几何，外部玻璃的原始 alpha 为 0.980。轮胎几何归集在同一网格中，节点树按材质分组。

### 灯组显示

网页副本从 `blac` 中分离两侧横向灯片，从 `emit` 中分离两侧竖向光刃，标记为 `extras.vehicleLamp = front`。分选使用原有连通面片，黑色灯框和座舱灯带保持独立，GLB 材质参数不变。运行时 `CarLights` 仅克隆这些灯片及尾灯的材质，设置冷白前灯与红色尾灯，并避免高光色调映射把尾灯冲成白色。原始 GLB 不改写。

灯晕由整车深度遮挡后的灯组遮罩生成，车身会挡住背面的光源；主相机合成轻微散射，车内机位停用此效果。遮罩长边上限为 1024 像素，轻量模式为 640 像素并关闭多重采样。

### 门、轮与座舱玻璃

两份网页副本以三角形连通关系合并 UV 与硬法线造成的边界重复，再按经对照的世界坐标范围分选零件。每侧门轴带动外门皮、窗框、侧窗、内门软包与前端饰件。后门缝内的车漆折边及其相连的黑色风道、门槛留在车身上。中央风挡、仪表、座椅和后舱壳体固定。GLB 将轮胎、轮桶、外轮罩和每轮的 62 片叶片收纳在同一轮轴下；运行时 `VehicleRig` 将四个 `Wheel_*_glass` 外轮罩保持世界变换不变地转挂到车身根节点，使其相对车身静止。轮胎、轮桶与叶片仍由行驶距离或风洞风速驱动，与概念车磁力系统保持轮罩静止的设计对应。[小米设计资料](https://www.mi.com/global/discover/article?id=5980)

`Door_L` 位于 −Z 侧，`Door_R` 位于 +Z 侧。展示铰点基于前门缝拟合，左右门沿镜像轴向上、向外开启 60°。这是模型展示运动设定。各枢轴的 `extras.motion.axis` 提供单位局部轴，车门另有 `angle`（弧度），四个 `Wheel_FL/FR/RL/RR` 枢轴另有 `radius`（米）。机位采用车头 +X、上方 +Y。两侧窗片与 `Windscreen` 节点携带 `extras.cabinGlazing`，可单独切换座舱视线中的玻璃表现。

核验涵盖闭合、部分开启、完全开启及回位。开门后门片最高点从 1.175 m 升至约 2.127 m，两片半顶向各自外侧分离。四个车轮旋转四分之一圈时外包络偏差在 4 mm 内。闭门姿态按材质逐三角形对照了拆分前后的有向顶点、法线、UV、切线、AO 和世界变换，两档均取得相同几何指纹。

### 减面与验证

两档分别从原件制备。先移除未被着色器使用的 UV、按材质合并、焊接完全相同的顶点，再使用带法线权重和锁边约束的误差简化。小型前后发光灯带与座舱镀铬细件直接保留。共享 16 位位置网格保持面板接缝对齐，14 位法线保留车漆反射所需的精度，轮胎法线贴图保留原始 PNG 字节。加载需为 Three.js 的 GLTFLoader 注册 MeshoptDecoder。

制备脚本重新读取两份压缩文件，对比 PBR 参数、材质名、署名、世界包围盒和所有解码法线的长度。验证脚本从六个方向以 720 × 400 栅格比较原件与副本的前表面，覆盖揭幕、侧影、前风道、轮圈、头灯和车尾。

烘焙阶段将各分块变换至世界坐标，以整车为求交对象。从顶点沿法线外偏 3.5 mm 后，使用双侧镜像的固定方向集采样 0.46 m 内的几何，按余弦及命中距离计算局部天空可见度。各网格将结果存储为归一化无符号字节标量 `_AO`。Three.js 读取为 `geometry.attributes._ao`，取值从 0（遮蔽）到 1（开阔），供间接光照着色使用。

### 复现

离线制备使用 Node.js、Python 3.10+ 及 Embree CPU 求交库。在此目录执行下列命令。脚本读取工作区根目录的 `models/xiaomi_vision_gt.glb`，将两份副本写入站点的 `public/models`。已有 Python 虚拟环境可用 `VISION_AO_PYTHON` 指定解释器路径。浏览和构建网站直接使用制备好的 GLB。

```sh
npm ci
python -m pip install -r requirements.txt
npm run prepare-models
npm run verify-models
```

可选命令 `node verify.mjs <目录>` 同时输出各机位的法线与遮蔽诊断图。原始 GLB 的 SHA-256 为 `c91dd45fa5484c499d853dd0b00736e5fb0694fbd951971d3ebb092a00346b7a`。

### 风洞绕流场

当前页面采用 OpenFOAM 黏性 RANS 平均流场与守恒被动标量输运，参考工况为 120 km/h，包含移动地面、旋转轮组和静止外轮罩。浓度只从入口注入；渲染另以有界光学增强显示贴壳和风道烟层，不修改 CFD 浓度。几何显示标记单独存于 `public/flow/contact.bin`，由 `prepare-contact.mjs` 从同模型的风道识别结果生成。车头低速区、底盘和尾流的诊断、三档网格结果、边界条件及复现命令见 [CFD 制备与核验](cfd/README.md)。

`public/flow/vision-gt.bin` 为 v4：256 × 96 × 128 网格，原生 RGBA16F 保存沿 CFD 速度反向追踪的行程时间、入口 Y/Z 与车身距离，RG8 保存原浓度和相对湍流强度。宽幅烟纹随材质坐标转向，入口显示遮罩突出迎风区域，按真实车身深度积分。流速由 km/h 换算为 m/s，高速使用曝光过滤；细小纹理仍属于平均场上的视觉重建。关闭喷烟后已有烟雾逐渐离开，车轮仍跟随设定风速；减少动态效果时使用定帧。

车尾另外读取 `public/flow/wake.bin`：126,768 单元局部 URANS 的 26 帧浓度记录，采样尺寸 64 × 32 × 48。数据通过浓度最大值原理、通量与时间步减半检查，首尾在播放时有界交叠接续；接入区域退出原有正弦摆动，未人为放大计算结果。原始坐标的车壳/玻璃排除和精确深度遮挡继续生效。该短时 URANS 记录变化较小，不等于真实脱涡频率、LES 或实验验证；其他风速仅缩放 120 km/h 的记录时标。来源和限制见 `wake-audit.json` 与 [CFD 制备与核验](cfd/README.md)，使用 `npm run verify-wake` 复核二进制。

CFD 采样的固体区域不能完全覆盖展示模型的薄玻璃和薄板。`contact.bin` v2 因而同时保留直接从 GLB 体素化的保守表面距离，烟雾只在两套边界都允许的外部区域显示；座舱保持封闭，真实模型深度另行截断视线后的烟。贴面和风道增厚使用这一边界，不改变已有 CFD 输运数据。

运行 `npm run verify-flow` 检查文件头、数据范围、实体内无烟、模型与流场指纹、压缩副本一致性；`npm run verify-contact` 在标准与轻量车模的每个三角形上取四点，检查薄板和玻璃表面不会被当成有烟区域，并检查风道标记仍保留。页面使用通过浓度检查的 56.5 万单元中等网格；128 万单元细网格用于误差对照，其局部浓度越界的烟场被拒绝。严格全场残差、边界层和工程阻力网格无关性尚未全部满足，也没有实车校准。因此它是可复查的定性展示，不能用来报告工程 Cd。

早期 `flow.mjs` / `flow-solver.mjs` 是单次压力投影与单向坐标输运，不包含黏性和湍流。文件保留作对照；`node flow.mjs <单独输出目录>` 不得覆盖现有 CFD 数据，旧格式使用 `npm run verify-potential-flow` 校验。

### 实时风阻估算

`src/aerodynamics.ts` 单独计算展示趋势，不从展示流场推导阻力。官方仅给出概念车 Cd = 0.29，未提供车速扫描或标定工况；本站**假设** 120 km/h 为展示参考速度，湿表面积/迎风面积比为 5，长度采用展示模型的 5.44 m，运动黏度取 1.5 × 10⁻⁵ m²/s。仅改变全湍流光滑平板的摩擦项：`Re = (km/h ÷ 3.6) × L / ν`，`Cf = 0.455 / log10(Re)^2.58`，`Cd = 0.29 + 5 × [Cf(Re) − Cf(Re120)]`。

1、60、120、300 km/h 的显示值分别约为 0.311、0.292、0.290、0.288。这是带明确假设的趋势模型，低速时尤其不能视为真实车身的转捩、分离或风道阻力结果。页面标注“估算”并提供说明；官方参考值始终保留。实际 Cd 需要测力或经验证的黏性 CFD，并匹配雷诺数与试验条件。依据 [NASA 对风阻系数及相似条件的说明](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/drag-coefficient/)；摩擦相关式见 [NACA TN 4318，图 5](https://ntrs.nasa.gov/api/citations/19930085111/downloads/19930085111.pdf)。


## 新车型轮组轴线

`articulate-wheels.mjs` 使用 `fit-wheel-profile.mjs` 从轮胎的窄主轴拟合实际转轴，在垂直于转轴的平面测量轮心和半径。不能把迈凯伦的轮组统一绕车身横轴转动：原作前轮有约 4.5°、后轮约 3.5° 的外倾，水平转轴会造成可见的摆动。模型外倾和关停姿态保持原作。

`npm run verify-wheel-alignment` 对标准和轻量两档的四轮做整圈检查，要求胎面沿原作轴向的漂移小于 0.02 mm、轮廓高度变化小于 1.5 mm；当前高度变化约 0.065–0.082 mm。`showroom/tools/stills/verify-driving.mjs` 另检查实际车速、路面行程与轮角增量一致。
